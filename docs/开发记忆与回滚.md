## 二、架构骨架（改东西前必须知道）

```
Electron 主进程
├── 窗口
│   ├── 主窗口（编辑器）        index.html
│   └── 草稿库窗口（单例）      drafts.html，1120×740，标题栏自绘
├── 协议 gewu://workspace/<rel>（当前草稿）· gewu://draft/<id>/<rel>（草稿库缩略图）· gewu://app/<rel>
├── DraftStore        %APPDATA%/gewu-video/drafts/<id>/{draft.json,chat.json,scene.json,AGENTS.md,assets,previews,exports}
│                     + drafts.json（activeId）+ trash/（软删除）
├── SceneStore        单个草稿的 scene.json、assets/、previews/、AGENTS.md 同步
├── ConfigStore       %APPDATA%/gewu-video/config.json，key 用 safeStorage 加密
│                     + exportSettings{dir, askEveryTime, revealAfterExport, recentDirs}
├── ModelProxy        本机 HTTP，把 OpenAI 兼容请求转发到真实服务；Key 只在主进程
├── Tts               Windows System.Speech 离线合成 wav，不需要 Key、不联网
└── AgentBridge       起一个隔离的 DSH 子进程，走 ACP(JSON-RPC over stdio)
    ├── DshProcess    vendor/dsh-runtime，带 gewu-acp.patch.yml（关掉所有宿主工具）
    └── ToolGateway   agent 能调的 14 个工具 → 一半直接改 scene.json，一半回渲染进程执行
```

关键约束（**别破坏**）：

1. **Key 绝不进子进程**。子进程只拿一次性 bearer token 连本机代理。
2. **agent 没有任何宿主工具**（bash/fs/web/skill/subagent 全关）。它只能通过工具网关改场景。
3. **画面只能依赖 `t`**。导出是逐帧渲染，任何跨帧状态都会导致视频抖动。
4. **`draw` 是函数体**，用 `new Function` 编译，渲染进程必须开 `'unsafe-eval'`。
5. **一个草稿 = 一个工作区目录**。agent 的 cwd 就是当前草稿目录，所以**切草稿必须换 cwd 并重启 agent**，
   不能只换内存里的路径（否则工具会写进旧目录）。

### 草稿箱（多草稿）

- 目录：`%APPDATA%\gewu-video\drafts\d-xxxx\`，索引 `drafts.json` 只存 `{version, activeId}`，
  其余信息（名字/时间/置顶）在各自的 `draft.json` 里——**索引坏了也不会丢草稿**。
- 老版本只有一个 `workspace/`：首次启动 `DraftStore.init()` 会整体 `rename` 成第一个草稿
  （跨盘才退回 `cp` + `rm`），名字取场景 `meta.title`，并置顶。
- 切草稿：`activateDraft(id)` → `bridge.isBusy()` 拦住 → `flushAll()` → 换 SceneStore →
  `bridge.newSession()` → 广播 `gewu:draft-opened`，渲染进程重载场景/对话并**清空 undo 栈**。
- 删除是软删除：`rename` 到 `trash/<id>-<时间戳>/`，**不允许删当前打开的草稿**。
- 复制草稿跳过 `exports/`（成片动辄几 MB，复制没意义）。
- 封面：渲染进程每 5 秒（且距上次 ≥1.6 秒）把画布缩到 480px 写进 `previews/cover.png`，
  草稿库用 `gewu://draft/<id>/previews/cover.png` 显示。

### 导出位置

- 优先级：`--export-path`（调试强制）→ 设置里固定的 `dir` → `recentDirs[0]` → 系统「视频」→ 草稿 `exports/`。
- 人点的导出走 `ExportDialog`（文件名 + 目录 + 最近目录 + 整段/只导一段 + 导出后打开文件夹）。
- agent 的 `saveWorkspaceExport` 走**同一套**目录规则，只是不弹窗。
- 同名文件自动加 `-1`…`-999`（`uniquePath`），**绝不覆盖**已有成片。

### 场景元素树（2026-11-03 加的手工剪辑基础）

```
SceneLayer
├── kind: group | text | image | shape | code   （省略 = code，兼容老场景）
├── x/y/w/h + scale/rotation（度，绕元素中心）
├── text{content,size,weight,color,align,lineHeight,maxWidth,font,background}
├── image{src,radius,fit,placeholder}
├── shape{type: rect|ellipse|line|arrow|triangle, fill,stroke,strokeWidth,radius}
├── draw  只有 code / 带动画的 group 才有
└── children[]  group 才有；坐标相对 group 左上角

Scene.guides?: { v: number[]; h: number[] }   用户参考线（设计坐标）：
  只影响吸附与显示，不参与渲染、不进导出；normalizeScene 会清洗（各 ≤40 条，空则不写进 scene.json）
```

## 三、踩过的坑（按疼痛程度排序）

### 1. DSH 工具 schema 必须显式写 `additionalProperties`

`type:'object'` 不写 `additionalProperties: true|false` → `UNSUPPORTED_SCHEMA` → 插件加载失败 → `session/new` 失败 → **agent 根本起不来**。
表现极具误导性：界面显示「正在启动」，日志里只有一行 stderr。

### 2. 画布跨域污染（今晚刚修）

`gewu://` 图片被当跨域，`getImageData` / `toDataURL` 直接抛
`The canvas has been tainted by cross-origin data`。
修法三件套，缺一不可：
- `registerSchemesAsPrivileged` 加 `corsEnabled: true`
- 协议响应加 `Access-Control-Allow-Origin: *`
- `new Image().crossOrigin = 'anonymous'`

### 3. `asset()` 原本返回字符串

`ctx.drawImage('gewu://...')` 必然抛错，而 AGENTS.md 一直这么教模型 —— 等于每个用图的场景都会报错。
现在 `asset()` 返回**已加载的 `<img>`**，另有 `g.image()` 糖。

### 4. `util.rad` / `util.deg` 曾经写反

旋转类动画全错。症状是图形变成密集网格（角度当弧度用，转了 57 倍）。

### 5. `store.load()` 忘了调用

填完 Key 重启就丢配置。

### 6. `bridge.start()` 并发调用

两处同时 start，后者覆盖状态，真实错误被吞成「正在启动 Mock LLM」。现在用 `startPromise` + `doStart()` 重抛。

### 7. PowerShell 会把源码写坏

`Get-Content` + `.Replace()` + `Set-Content` 曾把源码里的引号变成 `.`。
**改源码只用 edit 工具**。今晚有一次例外（`preview.ts` 的 `asset: imageFor → assetImage`），事后检查了 `\uFFFD` 计数为 0 才敢继续 —— 不要学。

### 8. `electron-vite build | Out-File` 会挂住

管道形式偶发卡死（进程退出但 pwsh 不返回）。**用 `*> file.log` 重定向**，不要用管道。

### 9. `Start-Process -NoNewWindow -RedirectStandardOutput` 会让 pwsh 任务永久挂起

启动 Electron 测试时不要用，直接 `& electron.exe . --xxx 2>&1 | Select-String …` 前台跑。

### 10. 残留的假模型 node 进程会让后续测试挂死

跑 `--selftest` 或 `--prompt` 之前先清场，否则 pwsh 任务会卡住不返回：

```powershell
Get-Process electron,node -ErrorAction SilentlyContinue | Stop-Process -Force
```

正常一次 selftest 大约 **11 秒**；超过 60 秒还没返回，基本就是被残留进程拖住了，直接清场重来。

### 11. Windows 上收不到 Electron 的 stdout

Electron 是 GUI 子系统程序，PowerShell 的 `>`、`*>`、`Tee-Object` 都**收不到**它的输出
（管道 `| Select-String` 有时行有时不行，别指望）。
`--log=<file>` 会把主进程的 `console.log/error/warn` 落到文件，联调一律用它：

```powershell
& electron.exe . "--prompt=…" --log=_run.log --exit-after
Get-Content _run.log
```

### 12. UTF-8 BOM 会让配置静默失效

`Set-Content -Encoding utf8` 在这个环境里**会写 BOM**，`JSON.parse` 见到 BOM 直接抛，
`ConfigStore.load()` 的 catch 把配置吞成空 → 界面报「未配置模型连接」，极难排查。
`load()` 现在会先剥掉 `\uFEFF`。**自己写配置文件时用**：

```powershell
[System.IO.File]::WriteAllText($path, $json, (New-Object System.Text.UTF8Encoding($false)))
```

### 13. 合成事件测 UI 时，React 状态不会同步生效

`dispatchEvent` 连发 `mousedown → mousemove → mouseup` 时，三个事件在同一个任务里，
React 还没重渲染，`mousemove` 的回调闭包里 `drag` 还是 `null`，框选永远出不来。
**每次事件之间要 `await wait(80)`**。另外画布用的是 `MouseEvent` 而不是 `PointerEvent`。

### 14. electron-vite build 偶发卡死

现象：进程在跑但 `out/` 不更新，pwsh 任务永不返回，node 进程只烧 1~2 秒 CPU，
日志停在 `transforming...`，任务管理器里通常还挂着两个 `esbuild.exe` 子进程。
删 `out/`、清 `node_modules/.vite`、加 `--debug` 都**不能**稳定解决，成功率大约一半。

**用 `scripts/build.ps1`**：超时（默认 75 秒）就杀掉重试，最多 4 次，靠
`out/renderer/index.html` 的时间戳判断成败（`Start-Process` 重定向下
`$p.ExitCode` 读不到，不要用它判断）。

```powershell
& .\scripts\build.ps1
```

注意：这个脚本必须保持 **ASCII**，Windows PowerShell 会把无 BOM 的 UTF-8 当 ANSI 读，
中文会把解析器搞崩。

### 15. `--selftest --full` 曾经会覆盖 `demo.mp4`
`--full` 原来直接写 `demo.mp4`，拿测试场景跑一次整段回归就把要交付的样片冲掉了。
现在固定写 `_selftest-full.mp4`。**样片要重新生成，手工把产物改名成 `demo.mp4`**，
并核对字节数应该是 `3240689`（偏振光 11 层 12 秒 30fps）。

### 16. 事件回调里读 React state，拿到的永远是旧值

`onBarDown` 里 `setDragBar(...)` 之后，`move` 闭包读到的 `dragBar` 仍然是 `null`
（state 还没提交、闭包也不会更新）。于是 `dragBar?.origEnd ?? duration` 退化成
`duration`，**拖时间轴右手柄会把 end 直接吸到片尾**。
凡是「mousedown 里记下的初始值 + mousemove 里用」，一律用 mousedown 时的**局部常量**，
不要绕回 state。

### 17. useEffect 依赖里放每帧都变的对象，循环会被反复拆掉

播放循环依赖了 `editor`，而 `editor` 是 `useMemo(..., [time, ...])`，
每次 `setTime` 都换新对象 → effect 清理 + 重建 → `lastTs` 重置 → `dt` 只量到一小段。
实测**点播放 2.1 秒，播放头只走 0.03 秒**。
循环类 effect 只依赖开关（`playing`），其余需要的东西走 ref。

### 18. 命中测试不能把整幅画缩到 4×4 再采样

`hitTest` 原来把 1920×1080 缩到 4×4 找 alpha，40px 的字、2px 的线缩完不到 0.1 像素，
alpha 约等于 0，**只有铺满画面的网格层能被点中**。
正确做法是平移画布、让点击点落在小画布中心，按 1:1 渲染一小块再取 3×3 最大 alpha。

### 19. 前端按 id 整条替换消息，回传时漏字段就等于删字段

`agent_message_chunk` 回传时没带 `tools`，而前端是「同 id 就整条替换」，
于是**agent 一开始吐字，本轮跑过的工具条就全没了**。
凡是「按 id 整体覆盖」的消息模型，每次回传都要把该带的字段带全
（现在统一走 `toolsFor(assistantId)`）。

### 20. tool_call_update 不带 title，却把 title 覆盖成「工具调用」

ACP 的 `tool_call` 带 `title: "scene_write"`，但后续的 `tool_call_update`
只带 `status`。原代码 `title = update.title ?? update.kind ?? '工具调用'`
在 update 上退化成「工具调用」，随后 `existing.call.title = title` 把它覆盖掉，
**界面上永远显示「工具调用」，看不到真实工具名**。
只有显式带了 title 才更新，其余保持原值。

### 21. ACP 错误帧的 `error.message` 被整条丢掉

`acp-process.ts` 收到 `frame.error` 时只拼了 stderr，**没用 `error.message` 和 `error.data`**，
结果 Key 填错时用户只看到一句「DSH session/prompt 失败」，完全不知道该改哪里。
真正的信息在 `data` 里（`Internal error: turn failed: API Key 无效…`）。
现在 `describeAcpError()` 把 message + data 摊平，`humanizeAgentError()` 再把
`DSH session/prompt 失败：` / `Internal error: turn failed:` 这些壳剥掉。

**教训**：错误处理里「有个 error 就 reject 一句固定话」是最容易埋雷的写法，
`error` 里能拿到的字段一个都别丢。

### 22. 图层里写 `const p = …` 会让整层静默消失

图层代码是 `new Function` 拼出来的函数体，前面已经 `const { ctx, t, p, … } = scope`。
再声明一个 `p` 就是重复声明，**编译期直接抛**，那层一个字都画不出来——
但界面上只看到「这层没了」，不知道原因。`p`（position / point 的直觉缩写）是最容易撞的名字。
现在 `compileLayer` 会把 V8 的原文翻译成「p 是内置变量，换个名字，比如 p2 或 pos」，
AGENTS.md 和检查器里的 API 速查也都写了这条。

### 23. Windows 上 `console.log` 重定向到文件，被强杀会丢缓冲

mock 把工具结果打到 stdout，`Start-Process -RedirectStandardOutput` 写文件，
杀进程时文件只剩一千多字节，工具返回的那 4856 字符全丢了，白白多跑两轮。
现在 mock 支持 `MOCK_LOG_RESULT=<file>`，用 `appendFileSync` 直接落盘。

### 24. `pnpm add` 会把 `node_modules/electron/dist` 删掉

装 electron-builder 之后，`node_modules/electron` 这个 junction 指向的 store 目录里
**`dist/` 整个没了**（postinstall 被 pnpm 跳过，但旧文件已被清理），
于是 `node_modules\electron\dist\electron.exe` 不存在，app 直接起不来。
当时另一份 store 副本 `.pnpm/electron@45.2.1/node_modules/electron/dist` 还在，
用 `robocopy` 拷回去就好了。

**以后动 `package.json` 依赖前，先确认 `node_modules\electron\dist\electron.exe` 还在。**

### 25. electron-builder 会把 extraResources 里的 node_modules 剔掉

`extraResources: [{from: 'vendor/dsh-runtime', to: 'dsh-runtime'}]` 只拷进来 **6 个文件**，
`node_modules` 整个被过滤掉了（加 `filter: ['**/*']` 也没用），
打出来的包一启动就报 `ENOENT ... dsh-runtime\node_modules\@deepseek-ai\dsh\package.json`。
所以 `scripts/package.ps1` 在 electron-builder 之后用 `robocopy /E` 再补一遍，并校验 marker 文件存在。

### 26. Electron 发行包下不下来（0 字节卡死）

`electron-builder` 默认要去 GitHub / 镜像下 `electron-v45.2.1-win32-x64.zip`。
这台机器上 HEAD 请求都 200，实际下载却一直卡在 0 字节（temp 里能看到 0 MB 的 zip），
换 npmmirror 镜像也一样。解法是 `electronDist` 直接指向
`node_modules/.pnpm/electron@45.2.1/node_modules/electron/dist`，完全不联网。

### 27. 用管道接 `electron-builder` 会永远挂住

`& $node ...cli.js --win --dir 2>&1 | Select-Object -Last 4` 这句，工作早就做完了
（exe、asar、dsh-runtime 全都在），但脚本永远不返回——electron-builder 派生的子进程
一直握着 stdout，管道不结束。**改成 `Start-Process -RedirectStandardOutput <文件>`**，
然后轮询 exe 是否出现、再 `WaitForExit(180000)`。

### 28. 杀掉构建任务后，`out/` 可能是坏的，而 `dist/` 看着是好的

`package.ps1` 里那步 `build.ps1` 有重试逻辑，如果中途被 kill，`out/` 会留下半套文件。
表现极其迷惑：**打包成功、exe 也在、双击却什么都不发生，连 `--log=` 都是 0 字节**。
排查时以为是打包坏了，其实是 `out/` 坏了。
**规矩：任何一次被中断的构建之后，先单独跑一次 `scripts\build.ps1` 再测。**

### 29. `ELECTRON_RUN_AS_NODE=1` 会让 Electron 秒退（只在 DSH 的 shell 里）

在 DSH 里跑的 pwsh 继承了一个 `ELECTRON_RUN_AS_NODE=1`，于是
`Start-Process electron.exe` 会**把 Electron 当纯 Node 跑**，立刻退出，什么日志都没有。
用户环境变量里没有这一项，所以**双击桌面快捷方式是正常的**。
只有在这类 shell 里做自动化测试时才要 `Remove-Item Env:ELECTRON_RUN_AS_NODE` 先。

### 30. 两个实例同时写 `config.json`，写成了半截 JSON

现象：界面报「未配置模型连接」，但 `config.json` 打开一看**内容都在**——
只是尾部多了一段上一次的残留（`}probe-out" ] } }`），`JSON.parse` 直接抛，
`load()` 的 `catch` 把配置吞成空。

两个成因，都要防：

1. **并发写**：两个进程（我同时起了两次探针）各写各的。→ `app.requestSingleInstanceLock()`。
2. **同进程内的重叠保存**：`setExportSettings` 里的 `save()` 是 fire-and-forget，
   连续改几次就会重叠；而原子写的临时文件名原来是 `pid + Date.now()`，
   **同一毫秒内两次保存撞名**，两个 `writeFile` 交错写出半截文件再 rename 上去。
   → 临时名加自增序号 + 随机后缀，并且 `save()` 用 promise 链**串行化**。

**规矩：所有「整份 JSON 覆盖写」都走 `electron/main/atomic.ts`**（`atomicWrite` / `atomicWriteSync`），
不要直接 `writeFile`。`app.exit()` 会绕过 `before-quit`，所以退出兜底用 `store.flushSync()`。

另外：`load()` 读失败时会**留一份 `config.json.bad-<时间戳>` 副本**，并置 `loadFailed`；
这种情况下 `flushSync()` **不会**用空配置回写（否则用户还能手工救回来的 Key 就没了）。
实测：故意写坏 160 字节的配置 → 启动后文件仍是 160 字节，旁边多一个 `.bad-` 副本。

### 31. 切草稿只改内存路径，agent 还在旧目录里干活

agent 是独立子进程，cwd 在 `session/new` 时定死。切草稿如果不重启它，
`scene_write` 会写进**上一个草稿**的 `scene.json`，用户看到的是「切过去了但画面没变」。
所以 `activateDraft` 必须：换 SceneStore → `bridge.newSession()`（重起子进程、新 cwd）。
另外 agent 正在跑的时候切换会把这轮工具调用撕成两半，**直接拒绝**并提示先停止。

### 32. 切草稿不清 undo 栈，Ctrl+Z 会把上个草稿的内容撤进这个草稿

`replaceScene` 默认保留历史（同一草稿内的 AI 改动要能撤）。切草稿时必须传
`{resetHistory:true}`，否则撤销栈里存的是旧草稿的 `layers`，一按 Ctrl+Z 就串了。

### 33. 草稿库窗口用 `gewu://workspace/...` 拿不到别的草稿的封面

`gewu://workspace/` 永远指向**当前**草稿。草稿库要显示所有草稿的封面，
所以加了 `gewu://draft/<id>/<rel>`（带 `safeJoin` 防穿越），
且响应头必须带 `Access-Control-Allow-Origin: *`，否则 canvas 一读就污染。

### 34. 场景从「一层代码」变成「元素树」，三处必须同时改

2026-11-03 加了结构化元素（`kind: group/text/image/shape/code` + `children`）。
这个改动不是加个字段那么简单，**渲染、命中、归一化**三处必须按同一套坐标系走：

- `src/engine/render.ts`：`renderScene` 递归 `paintList(layers, env, basePath)`，
  每层用 `ctx.save/translate/rotate/scale` 叠祖先 transform，路径数组当身份（`pathKey`）。
- `src/components/stage-geometry.ts`：`layerMatrix/worldMatrix/worldToLocal/pointInTyped`。
  命中和绘制**必须共用**这一份矩阵，否则「画在这、点不中」。
- `electron/main/scene-store.ts`：`normalizeScene` 递归清洗（`MAX_DEPTH=4`、`MAX_LAYERS=300`），
  只允许白名单 kind，`draw` 只对 `code` 必填。

漏改任意一处就会出现「画面有、点不中」或「保存后子元素消失」。

### 35. 组合要有自己的盒子，子元素坐标相对组合

`editor.group()` 会把选中元素的并集盒子写成组合的 `x/y/w/h`，并把子元素的 `x/y`
减去这个原点；`ungroup()` 再减回去。这样组合才能整体旋转/缩放（绕自己的中心），
而不是绕画布原点转。

反过来说：**AI 写 `children` 时坐标要相对组合左上角**。如果 AI 写绝对坐标、
组合又有非零 `x/y`，画面会整体偏移。老场景（`x=0,y=0` 的扁平图层）不受影响。

### 36. 画布聚焦时 Ctrl+Z 失效（全局快捷键被 `[data-canvas]` 提前 return）

全局 `keydown` 里为了不让方向键和画布微调打架，写了
`if (target.closest('[data-canvas]')) return`。但撤销/重做也在这之后，
结果点过画布之后 Ctrl+Z 完全没反应。**撤销/重做必须放在这个守卫之前**
（输入框判断 `typing` 仍在最前面）。

### 37. 拖动时别「冻结」选择框

一开始为了省掉 code 图层的像素扫描，拖动时把选框缓存住，结果拖动过程中框不动、
松手才跳过去，手感很差。正确做法：选框永远从当前 scene 现算
（`liveBoxes`），手势起点只缓存「原始 x/y」用于算增量。

### 38. 探针里 `flat()` 少映射字段，断言就会假失败

写探针时把图层拍平成 `{id,name,x,y,...}` 方便比较，但 `byName()` 拿它查 `text.content`，
字段没映射进去 → 永远是 `undefined` → 断言假失败，白查半小时。
**拍平函数要么映射全部用到的字段，要么直接返回原对象。**

### 39. 时间轴上「满时长」的剪辑块拖不动

`mode==='move'` 里 `clamp(origStart+dt, 0, dur-len)`，一个 `start=0,end=duration`
的图层 `dur-len=0`，怎么拖都回 0。这是对的（它没有可移动空间），
但看起来像 bug——探针里要先裁短再拖。

### 40. `--selftest` 导出的是「当前草稿」，帧数随草稿时长变

导出回归的 `frames` 不是固定值：`frames = duration × fps`。
2026-11-03 的探针草稿改成 8s 后，`--selftest` 是 96 帧、`--selftest --full` 是 240 帧。
判断回归要看 `ok:true` + `container:"mp4"` + 帧数对得上草稿时长，别死记字节数。

### 41. React 的 setState 更新函数里算出来的 id，返回给调用方时还是空的

`editor.duplicate()` 原来在 `updateScene(s => …)` 的回调里 `created.push(copy.id)` 再 `return created`。
React 18 的更新函数是**延后执行**的，所以函数返回时 `created` 还是空数组。
后果：时间轴 `Alt+拖` 拿不到副本 id，只能拖原件（原件跑了、副本留在原地）。
**新 id 必须在调用时同步算好**（`sceneRef.current` + `collectIds`），更新函数只负责插进去。
`paste()` 同理。

### 42. 对齐要算「组合自己的盒子」，`hasOwnBox()` 不含 group

`worldBox()` 只认 text/image/shape，组合返回 null。多选里混一个组合，
对齐/等距会把它当空气（3 个元素只剩 2 个参与，等距直接不生效）。
`layer-ops.ts` 里另写了 `boxOf()`：有 `w/h` 的（含组合）都走 `worldMatrix` 四点变换。

### 43. 换父级必须换算坐标（还有旋转），否则拖进组合会跳

`moveTo()` 原来只改树，不动 `x/y`：根层级 (600,820) 拖进 (240,180) 的组合后，
变成相对坐标 (600,820) → 画面直接飞出去。`computeReparent()` 把世界坐标折回新父级局部坐标，
再按祖先累计旋转差补偿 `rotation`（**scale 没补**，父级有缩放时换父级会变形，先记着）。

### 44. 探针里合成 mousedown 之后，要等 React 挂上 window 监听

时间轴的拖动/裁剪是在 `useEffect` 里往 window 挂 `mousemove/mouseup` 的。
合成事件下 `mousedown` 之后只等 90ms 有时还没挂上，第一个 `mousemove` 被丢掉，
后面算出来的位移就是错的（表现为「裁短直接到最小值 0.2」）。
**每次合成 mousedown 之后等 ≥150ms 再发 mousemove。**

### 45. 「鼠标移出就关」的下拉菜单，会把点菜单变成点底下的按钮

标题栏 ⋯ 菜单原来是 `onMouseLeave` 关闭，而它紧贴在按钮行下面。
鼠标从菜单往上挪一点（作者描述为「碰到草稿库的上边界」）就离开菜单 → 菜单消失 →
紧接着那一下点击落到刚露出来的「草稿库」按钮上 → **草稿库窗口莫名其妙弹出来**。
两个修法一起上：

1. **菜单只在点击时开关**（点外面 / Esc / 点菜单项），不再靠 hover 关。
   点标题栏里的按钮时，这一次 mousedown 只用来关菜单，并吞掉随后的那一次 `click`
   （`window` 捕获阶段 `stopPropagation`），否则「关菜单」和「点按钮」会同时发生。
2. 下拉内部（`.tb-menu` / `.tb-drafts`）的 mousedown 不触发关闭，交给菜单项自己的 onClick——
   否则元素在 mouseup 之前被卸载，菜单项的点击就丢了。

教训：**凡是「hover 关闭」的浮层，只要它和别的可点元素贴边，就一定会被点穿。**

其中 `kf` 是首尾帧完整链路：`asset_import ×2 → image_inspect → image_compare → scene_write → 多帧自检 → 导出`，
用来在没有真实 Key 的情况下验证「图生视频」整条路径。
`tts` 验证 agent 自己配音：`tts_speak → scene_write`（把返回的 path 写进 audio）。
`check` 对当前场景跑 `check_scene`（配合 `MOCK_LOG_RESULT` 读结果），用来检查整条时间轴有没有运行时错误。
`slow` 每 400ms 吐一段、共 60 秒，用来测「停止」按钮。
`nostream` / `reject400` / `auth401` / `reasoning` 专门测真实服务的四种脾气：
忽略 stream、不认 stream_options、Key 不对、先吐 `reasoning_content`（deepseek-reasoner）。

### 手工验收清单（给作者，5 分钟）

**发之前必须验三件事**（都做过一遍才算完）：

1. 分卷合并后与完整 zip 的 SHA256 一致（`copy /b a.001+a.002+a.003 out.zip`）。
2. 解压出来的 `运行版\Gewu.exe` 能跑：`--probe-file=scripts\probe-help.js` → 23/23。

坑：

- **`.exe` 不能直接发微信**，必须压成 zip；对方解压后双击，Windows 会弹

- 打包版**不转发渲染进程 console**（`isDev` 才挂），所以打包版跑 `--selftest` 看不到输出，

### 视觉模型（2026-11-03 加的）

**怎么用**：设置 →「视觉模型（agent 用它看图）」下拉，指一条多模态连接
（`gpt-4o` / `qwen-vl-max` / `glm-4v`，任何 OpenAI 兼容的都能用）。
不选就跟随当前对话连接——如果主模型本身能看图，什么都不用配。

**agent 侧两个入口**：

| 入口 | 行为 |
| --- | --- |
| `image_describe({ path, question? })` | 把工作区里的图发给视觉模型，返回中文描述 |
| `scene_render_frame({ t, describe: true })` | 正常返回字符预览 + 包围盒，再追加一段「视觉模型看到的样子」 |

**实现要点**（改之前先看）：

- `electron/main/vision.ts`：`toVisionDataUrl()` 用 Electron 自带 `nativeImage`
  把图压到最长边 1280 的 JPEG（1920×1080 的 PNG → 约 5–54 KB），再 POST `/chat/completions`。
  **不引第三方图像库**。
- Key 只在主进程解密（`store.getVisionConnectionSecret()`），渲染进程和 DSH 子进程都碰不到。
- 报错分三种说人话：401/403 → Key 不对；响应里出现 image/vision/multimodal → 换多模态模型；
  超时 → 等了 90s。
- 删掉视觉连接时 `store.remove()` 会把 `visionConnectionId` 置回 null，不留悬空 id。

**已知局限**：只验证过假模型。真实的 GPT-4o / Qwen-VL 还没试过，
prompt 是按「客观描述供代码复现」写的，可能要按实际效果调。
